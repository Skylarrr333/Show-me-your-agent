# 当前架构（2026-09-26）

## 主页面的数据路径

`components/home-finder.tsx` → `/api/homes` → `agents/home-agent.ts` → `lib/resale-store-runtime.ts` → SQLite。

它复用原项目的 `SessionSchema`、HttpOnly 会话 cookie、`lib/store-runtime.ts` 的版本冲突检查与原子保存、`agents/orchestrator.ts` 的 `event()` 审计记录，以及 `/api/refresh` 的刷新入口。由于 Kaggle 没有卧室、坐标等原 PropertySchema 必填字段，新主流程使用专门的 `HomeStateSchema`；不伪造这些字段来适配旧的72套房源。

一次搜索：读取旧状态 → 模型解析文字或直接使用表单 → 校验类型和独立预算锚点 → 带参数 SQL 检索 → 检查硬约束/拒绝/模拟事件 → 当前批次排序 → 推荐短名单 → 等待人审。模型只提取结构化需求，不生成 SQL、不执行任意工具；这是受控的单 Agent 工作流。

`/api/homes/action` 处理收藏、拒绝及原因、换一组、调整短名单、批准、重新检查、模拟下架/涨价和批量通勤检查。操作带会话版本；冲突时返回409。批准前重新检查数据库版本；数据不可核实则撤销批准。相同快照无需重新调用模型。

## 检索与推荐

保留队友的 SQLite 参数化查询。字段为预算、平方米、town、flat type、street、reference month；排序字段白名单，文本参数绑定。没有向量数据库、embedding或网页抓取。

源表 `resales` 包含228,225条交易，导入时用窗口函数按 town/block/street/type/storey/area/model/lease 分组，先取最新交易生成 `homes` 表，再执行用户预算筛选。这样不能用同组较旧的低价格让超预算房屋重新出现。

批次默认20个分组；评分 `60 + min(25,预算余量百分比) + min(15,平方米/10)`，硬通勤已通过者优先，并在可能时选不同楼栋。只是当前批次的可解释原型评分，非全库最优排名或估价。替代推荐记住已展示的组；需要时读下一页。

分组键来自地址/类型/楼层带/面积等字段，不依赖 CSV 行号。拒绝和模拟事件在重排或源文件行号变化后不会误指向其他房屋。收藏属于同一私有浏览器会话；换数据版本会清空旧收藏快照，避免把旧数据当成最新证据。

## 地图与通勤

`/api/homes/map` → `lib/maps.ts`：

- OneMap搜索准确楼栋号和道路名称；不匹配时不替换成town中心点。
- Overpass查询附近1km内选定类别，按直线距离展示；不能证明不存在其他设施。
- FOSSGIS OSRM返回walk/car路网距离、预计时间和路线几何。不是Haversine乘速度，也不是实时交通。
- OneMap公共交通路由需要额外鉴权，本版不声称接通；transit提供Google Maps跳转。
- `Check travel times`只检查短名单与有限备选，通常6套；人工扩展后最多12套。硬性通勤上限需要成功且匹配当前目的地/交通模式的路线证据，未知/超限无法批准。
- 每个上游在单进程中序列化为不超过每1.1秒1次；结果内存缓存（地址/设施24h、路线1h）、超时、固定查询模板、无全库自动地理编码。生产部署只有一个app实例；扩容须共享限流或更换服务。

前端Leaflet显示用户选择的类别和路线；外部标签作为纯文本弹窗，不插入HTML。地图服务收到的是用户主动查询的地址/目的地，不是完整聊天、密钥或cookie。瓦片按浏览器HTTP缓存，不预加载地图切片。

## 来源变化

页面可见时每60秒检查导入快照的SHA256；并非后台外部房源同步。导入新版本后重检并撤销批准。模拟下架/涨价仅作用当前会话，不改原始成交数据。下架不代表真实在售数据；没有真实房源接口、定时抓取或外部撤牌识别。

## 部署

Docker的Python数据阶段校验压缩包中的CSV并生成SQLite；最终Node22容器拷入只读数据库。`HDB_RESALE_DB` 指向 `/app/data/hdb-resales.sqlite`，会话写到独立持久卷。`/api/homes` 是容器健康检查入口，缺数据库不能报告健康。Caddy负责HTTPS和团队访问密码，模型密钥仅服务器可见。

Cloudflare/D1适配器继续保留，构建测试不代表已导入D1或已发布该平台；本次交付针对Lightsail。

## 旧模块

`components/workspace.tsx`、原 `/api/run`、`/api/action`、`/api/compare` 及72套虚构房源用于原场景回归。它们没有被冒充成Kaggle房源。旧通勤的直线公式仅属于旧测试场景，新主页面用真实路网返回结果。`training/` CPU排序实验不用于当前主页面，也没有训练本地大语言模型。
