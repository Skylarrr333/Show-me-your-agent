# Optional offline ranking experiment

This is separate from the competition's live DeepSeek agent. Production uses the original deterministic ranker. This package trains a small nonnegative pairwise logistic scorer on a CPU; it does not fine-tune an LLM.

```bash
npm run train:ranker
```

Outputs are `artifacts/dataset.json`, `ranker.json`, `metrics.json`, `prediction-example.json`, and `REPORT.md`. Labels are generated by an explicitly invented preference policy on fictional listings. Synthetic performance is only evidence that the training pipeline works, not of user preference or business benefit.

The generator separates buyer profiles and listing areas across train (120 buyers), validation (40) and test (40). The validator rejects buyer/profile/listing/building leakage, missing relevance labels, invalid numbers and duplicate IDs. L2 is selected on validation NDCG@3; only then is test evaluated. Pairwise ties score 0.5. Inference recomputes hard eligibility before calculating learned utility; it cannot make a disallowed listing eligible. Utility is not a probability or fit percentage.

For future human labels, create the same DatasetSchema structure, use `labelSource: human-reviewed`, provide relevance 0–3 from reviewers, and split by buyer plus building before labeling. Describe consent, dates, annotators and adjudication in `description`; keep real buyer data outside version control, for example under ignored `training/private/`.

```bash
npm run train:ranker -- --data training/private/reviewed.json --out training/private/experiment
```

The program trusts the declared label provenance, so human labels still require independent review. Do not relabel generated targets as human feedback. Do not train and test on different pairs from the same buyer or building. Obtain enough real, permissioned labels and beat a strong held-out baseline before considering runtime integration.
